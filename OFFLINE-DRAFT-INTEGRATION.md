# Draft adapter acceptance, offline
Reproducible: node --test test/*.test.mjs. The tests inject local HTTP-shaped fixtures, never authentic calls or credentials. The Mac .mcpb still has no route to this adapter. No release or remote branch change is required.

A suggested secure live design needs a trusted human approval surface (for example a locally signed Mac confirmation) which reviews and signs the exact SHA-bound local draft bytes, caption and target. The server pins the matching public key and deployment ID, checks a five-minute window, and re-hashes the fixture before media transfer. The test signer is an ephemeral synthetic key, not an implementation or verification of Mac UI, user presence or protection of a real key. Do not sign arbitrary model text, let Claude invoke the signer, or use a confirmation phrase as authorization. A live pilot needs a separate authorized signing/setup decision. The same trusted owner-only ledger must survive restart and never be deleted to retry; a saved or uncertain target blocks further POSTs. A token is a replayable credential until the bound attempt is reserved; keeping a single owner-only ledger is a necessary boundary.

The fake transport exercises exact accounts, separate MP4/PNG presign and PUT, draft-only POST with explicit idempotency, no calendar/publication fields, and per-platform cover and readback. Lost POST response leaves the target held until exact matching draft readback; no resend. A read-only check holds unknown or expired temporary media independently by video and cover. Independently verified permanent storage is not subject to the temporary seven-day window, but a draft's existence alone is not that verification. A later repair would need a separate owner-approved action and readback of the same original draft ID with the corrected cover; the test simulates only the readback. No edit, schedule, or promotion action exists.

At go-live, confirm the approved human approval surface, scoped Samantha account access, actual presign/GET shapes, exact provider storage readiness, and one separately authorized real draft. Elia reports the Chat demo worked; that does not verify these production gates.
